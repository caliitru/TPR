# Extend TPR with policy-gated source collection, intelligence and moderation

Phase 2 extends the existing fixture implementation with a configurable source registry, versioned permissions, persistent quotas/schedules, source health/audit, and mocked YouTube Data API, RSS/Atom, manufacturer and approved forum/generic API adapters. Discovery checkpoints commit with each page, retries preserve progress, and manufacturer facts/revisions remain separate from player evidence.

Includes DNS/SSRF address pinning, retained TLS verification, timeout/response bounds, conditional requests, shutdown controls, retention/tombstones/retractions, structured extraction-provider contracts, expanded product identity, manual match corrections, and source/job/fact/export controls in the authenticated admin API/UI and CLI. Also fixes structured-evidence hash revisions while preserving unchanged legacy fixture approvals and prevents the fixture worker claiming external jobs.

Validation: lint, strict TypeScript checks, build, 211 passing tests (171 unit/contract and 40 PostgreSQL/API integration), reversible migrations, original fixture demonstration, four-adapter mock demonstration and compiled HTTP smoke. Mock runs produce five observations plus one separate fact; repeat ingestion adds zero observations. Tests cover disabled/expired sources issuing zero requests, quotas, checkpoints, failure recovery, policy races, review/retention and TLS/SSRF response bounds without real source network calls.

All real collection and publication remain disabled. Policies can authorize mock runs only; no live activation command exists. No Lovable/Supabase connection, scoring change, real collection or deployment occurred. Live rights, credentials, deployment authorization and operational validation require separate approval. This PR targets `feat/fixture-intelligence` to isolate Phase 2 from the unmerged Phase 0/1 baseline. See `docs/PHASE2-OPERATIONS.md` and `docs/PHASE2-IMPLEMENTATION-REPORT.md` for reproduction and limitations.
